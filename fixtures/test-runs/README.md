# Test-run fixtures

Run folders for the test-review module, laid out like a real `feature-test` run. A run lives in its session folder
(`<home>/sessions/<id>/run/`), and the test plan and bug folders are copied into it, so each fixture here is one run folder
that is complete on its own. They are plain files (not git-ignored, not generated by `npm run fixture`); vitest reads them
directly, and the fixture scripts copy one into the `run/` folder of a generated session.

```
demo/run/                            the run folder (alias `run` = .)
  test-run.json                      the index the publish skills write (valid against TestRunIndexSchema)
  steps.md
  plan/test-plan.md                  alias `plan` = plan (a copy of the plan)
  bugs/x/{x.md, screenshots/1.png}   alias `bugs` = bugs (copies of the bug folders)
  logs/run.log
  scenarios/s1-pass/               videos/test-1-pass-1.mp4, screenshots/s1-01-a.png, screenshots/raw/, data/out.json
  scenarios/s2-fail/               like s1, linked to bug `x`
  scenarios/s3-gap/                screenshots only, linked to gap `g1`
```

What `demo/run/test-run.json` covers: three scenarios (pass; fail with a bug link, a markdown-only `stepsMarkdown` and
a video chapter; gap with a gap link), an overview with one panel of every known type plus an unknown
`"type": "weird"` (parses as `unsupported`), `pages: ["gaps", "logs"]`, one declared log with scenario excerpts,
and the roots `run`, `plan`, `bugs`. Every root stays inside the run folder (no `..`). The media are a few KB each: 48x32 PNGs and a 2 s 64x64 H.264 clip.

## Runs from real feature tests

- `state-management/run/` (about 1.1 MB): the DEMO-15267 run, 6 scenarios, 3 bugs, data setup, 4 logs, JPEG screenshots
  and 8 s MP4 clips cut from the source recordings. `db-snapshots/*.sql` is a placeholder.
- `withdrawn-repropose/run/` (about 0.5 MB): no test plan, no data setup, 9 scenarios, the three source notes under
  the `notes` root, and a `timeline` panel the dashboard does not know (renders as unsupported).

Check one with `npx tsx cli/src/index.ts run-index validate fixtures/test-runs/<name>/run`.

A real run gets its plan and bugs the same way: `ai-review run-file add <id> plan <file>` and `ai-review run-file add <id> bug <folder>` copy them into the run, and `ai-review run-file refresh <id>` copies them again when the originals changed.
