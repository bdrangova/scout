# Test-run fixtures

Run folders for the test-review module, laid out like a real `feature-test` output. They are plain files (not
git-ignored, not generated by `npm run fixture`); vitest reads them directly and `scripts/make-fixture.ts` copies
the `demo` tree next to a synthetic repo when it builds a test-run session.

```
demo/plans/f/a/                      the plan folder (alias `plan` = ../.. from the run folder)
  test-plan.md
  bugs/x/{x.md, screenshots/1.png}   alias `bugs` = ../../bugs
  test-runs/run-1/                   the run folder (alias `run` = .)
    test-run.json                    the index the publish skills write (valid against TestRunIndexSchema)
    steps.md
    logs/run.log
    scenarios/s1-pass/               videos/test-1-pass-1.mp4, screenshots/s1-01-a.png, screenshots/raw/, data/out.json
    scenarios/s2-fail/               like s1, linked to bug `x`
    scenarios/s3-gap/                screenshots only, linked to gap `g1`
```

What `run-1/test-run.json` covers: three scenarios (pass; fail with a bug link, a markdown-only `stepsMarkdown` and
a video chapter; gap with a gap link), an overview with one panel of every known type plus an unknown
`"type": "weird"` (parses as `unsupported`), `pages: ["gaps", "logs"]`, one declared log with scenario excerpts,
and the roots `run`, `plan`, `bugs`. The media are a few KB each: 48x32 PNGs and a 2 s 64x64 H.264 clip.

## Runs from real feature tests

- `state-management/plans/state-management/` (about 4.4 MB): the QI-15267 run, 6 scenarios, 3 bugs, data setup, 4 logs, JPEG screenshots
  and 8 s MP4 clips cut from the source recordings. `db-snapshots/*.sql` is a placeholder.
- `withdrawn-repropose/plans/withdrawn-repropose/` (about 0.5 MB): no test plan, no data setup, 9 scenarios, the three source notes under
  the `notes` root, and a `timeline` panel the dashboard does not know (renders as unsupported).

Check one with `npx tsx cli/src/index.ts run-index validate <run folder>`.
