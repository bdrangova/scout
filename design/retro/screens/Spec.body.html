QI-15472: Trial bar

  • Status: In Review
  • Assignee: Alex Rivera
  • Type: Story
  • Priority: Medium
  • Link: https://example.atlassian.net/browse/QI-15472

Description

Users on a free trial have no visible reminder of how many days are left, so many are surprised when the workspace becomes read-only. Add a persistent trial bar above the application header that shows the remaining days, turns amber when the trial is about to expire, and links straight to the upgrade flow. The bar must not appear for paid plans and must be dismissible for the rest of the browser session.

Acceptance criteria

  1. On the free plan a trial bar shows "Your trial ends in N days" (or "today" when N = 0) above the header.
  2. The bar turns amber when 3 or fewer days remain and stays neutral otherwise.
  3. Clicking "Upgrade" opens the upgrade flow; the chosen plan is confirmed without a full page reload.
  4. The bar is hidden for paid plans and stays dismissed for the rest of the session after the user closes it.

Implementation plan [[i:hard-drive]]

Implementation plan: trial bar (QI-15472)

Approach

Render the trial bar from app.ts next to the existing notice component instead of adding a new layout layer. The trial state comes from the /me response, so no new endpoint is needed; the warning threshold and the upgrade URL live in config.ts so support can tune them.

Steps

  1. Add trial (days left, plan) to the app state and read it during bootstrap.
  2. Create components/TrialBar.tsx with the neutral and amber variants, plus styles/trial-bar.css.
  3. Rename Banner to Notice: the old name clashes with the marketing banner and the trial bar.
  4. Remove legacy/OldBanner.ts; it has had no callers since the navigation rewrite.
  5. Wire the upgrade button to the billing flow and confirm the chosen plan inline.
  6. Cover the day formatting and the amber threshold with unit tests.

Out of scope

  • Server-side trial extension.
  • Emails about the trial ending.
